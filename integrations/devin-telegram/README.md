# devin-telegram

Локальный защищённый шлюз: Telegram → облачная сессия Devin через официальный REST API v1 (`https://api.devin.ai`).

Схема: `Telegram → bot.mjs (long polling) → Devin API v1 → ответ сессии → Telegram`.

Мультисессии: у каждого чата и каждой темы (topic) — своя привязанная сессия Devin. Личка, темы «правка шапки», «правка футера», другие группы — независимые каналы. Ответы Devin помечаются `[название темы/сессии]`, поэтому всегда видно, какая задача ответила.

## Безопасность

- Команды выполняет только владелец — `TELEGRAM_OWNER_ID` (allowlist по Telegram user ID).
- Токены живут в `.devin/telegram-bot.env`, который в `.gitignore`. В Git не попадают.
- `/cancel` останавливает сессию Devin и требует явного `/cancel confirm`.
- Любые разрушительные действия внутри сессии (push, deploy, удаление) по-прежнему подтверждаются в самой сессии Devin.

## Настройка

1. В Telegram откройте `@BotFather` → `/newbot` → получите токен.
2. В Devin откройте **Settings → Devin API → API keys (legacy) → Personal API key → View key** и скопируйте ключ `apk_user_...`. Важно: API v1 принимает только персональный ключ — токены сервисных пользователей (вкладка Service users) отклоняются с `403 Unauthorized`.
3. Скопируйте конфиг:

   ```powershell
   Copy-Item integrations\devin-telegram\.env.example .devin\telegram-bot.env
   ```

4. Заполните `.devin/telegram-bot.env`:

   | Переменная | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен от BotFather |
   | `TELEGRAM_OWNER_ID` | ваш числовой Telegram user ID (можно оставить пустым — см. ниже) |
   | `DEVIN_API_KEY` | персональный ключ `apk_user_...` (см. шаг 2) |
   | `DEVIN_SESSION_ID` | опционально: `devin-...` для привязки существующей сессии |
   | `BOT_ORIGIN` | `local` (ваш ПК) или `cloud` (облачная VM) — метка сессий |

5. Узнать `TELEGRAM_OWNER_ID`: оставьте поле пустым, запустите бота, отправьте ему `/whoami` — он вернёт ваш ID. Впишите его и перезапустите.

## Запуск

```powershell
node --env-file=.devin/telegram-bot.env integrations/devin-telegram/bot.mjs
```

или из папки интеграции:

```powershell
cd integrations\devin-telegram
npm start
```

На Windows есть готовый запускатель (сам находит `node.exe` и конфиг в корне репо):

```cmd
integrations\devin-telegram\start-bot.cmd
```

### Автозапуск при входе в Windows (постоянная работа на своём ПК)

Зарегистрируйте бота в Планировщике задач — он будет стартовать при входе в систему и переживать перезагрузки:

```powershell
schtasks /Create /TN "DevinTelegramBot" /SC ONLOGON /RL LIMITED /TR '"C:\путь\к\HUNDESALON_NIKA\integrations\devin-telegram\start-bot.cmd" --log'
```

Флаг `--log` пишет вывод бота в `.devin\telegram-bot.log`. Задача запускает `start-bot.cmd` напрямую — так путь с пробелами работает корректно (обёртка `cmd /c "..."` теряет кавычки при хранении в Планировщике). Проверьте, что задача записалась как надо: `schtasks /Query /TN DevinTelegramBot /XML`.

Проверить: `schtasks /Run /TN "DevinTelegramBot"`, остановить: `schtasks /End /TN "DevinTelegramBot"`, удалить: `schtasks /Delete /TN "DevinTelegramBot"`. Запускайте только один экземпляр бота — Telegram long polling допускает одного слушателя на токен; второй процесс (например, облачный и локальный одновременно) начнёт перехватывать сообщения друг у друга.

## Команды бота

- `/status` — состояние шлюза и активной сессии этого чата.
- `/list` — список сессий этого чата с метками.
- `/use N` или `/use devin-...` — переключить активную сессию чата (номер из `/list`).
- `/new` — следующий запрос создаст новую облачную сессию.
- `/bind devin-...` или `/bind https://app.devin.ai/sessions/devin-...` — привязать существующую сессию.
- `/cancel` → `/cancel confirm` — остановить активную сессию чата.
- `/whoami` — показать Telegram user ID и chat ID.
- Любой другой текст отправляется в активную сессию чата; ответы пересылаются обратно с меткой `[название сессии · облако|локально]` (длинные — частями). Метка показывает, какой шлюз создал сессию: `BOT_ORIGIN=cloud` → `· облако`, иначе `· локально`.

Привязки сессий по чатам сохраняются в `.devin/telegram-bot.state.json` и переживают перезапуск бота.

## Групповые чаты

Чтобы дать боту несколько параллельных задач, создайте группы и добавьте туда бота — у каждой группы будет своя сессия.

1. В `@BotFather` выполните `/setprivacy` → выберите бота → **Disable** (иначе бот не увидит сообщения в группах).
2. В группе пишите `@<бот> <задача>` или отвечайте на сообщения бота — на чужой разговор бот не реагирует.
3. Команды вида `/status@<бот>` работают и в группах.

### Режим тем (форум): задача = тема

Рекомендуемый режим: одна группа с включёнными **Topics** — каждая задача отображается отдельной темой, как канал.

1. В настройках группы (Edit) включите **Topics**.
2. Сделайте бота администратором с правом **Manage Topics** (иначе он не сможет создавать темы — HTTP 400).
3. На верхнем уровне (тема General или не-форум) пишите `@<бот> <задача>` — бот создаст тему с названием из текста задачи (например «правка футера») и привяжет к ней новую сессию Devin.
4. Внутри темы любой текст без упоминания идёт в её сессию — тема ведёт себя как отдельный канал задачи.
5. Если группа не в режиме тем, бот просто привязывает сессию к самой группе.
