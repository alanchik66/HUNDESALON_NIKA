# Тонкие неоновые линии: Canvas и эталон помощника

Внутренняя техническая справка проекта [[01_Projects/HUNDESALON_NIKA]]. Правила фиксации знаний: [[02_Areas/Operations#Verified knowledge capture]]. Дата проверки источников, кода и измерений — 2026-11-05.

Связанный код: [assets/js/menu-contour.js](../../assets/js/menu-contour.js). Регрессионные проверки: [tools/nav-pill-parity.test.mjs](../../tools/nav-pill-parity.test.mjs). Эта заметка относится к отрисовке декоративных линий, а не к физике погодной сцены.

## Проверенные технические факты

- В Canvas 2D `shadowBlur` и смещения тени не изменяются текущей матрицей преобразования. Для алгоритма размытия стандарт задаёт `sigma = shadowBlur / 2`. Поэтому установка DPR через `setTransform()` сама по себе не масштабирует параметры тени; координаты геометрии и параметры тени нужно учитывать отдельно. Источник: [WHATWG HTML — Shadows](https://html.spec.whatwg.org/multipage/canvas.html#shadows).
- CSS filter functions работают в sRGB. Фильтр элемента применяется к собранному изображению его содержимого и потомков. Это отличается от повторного рисования цветного ядра для каждого эффекта свечения. Источник: [W3C Filter Effects — filter property](https://www.w3.org/TR/filter-effects-1/#FilterProperty).
- CSS `hue-rotate()` соответствует матричному преобразованию `feColorMatrix` типа `hueRotate`. Замена только H в HSL не воспроизводит эту операцию. Источник: [W3C Filter Effects — hue-rotate](https://www.w3.org/TR/filter-effects-1/#huerotateEquivalent), [матрица hueRotate](https://www.w3.org/TR/filter-effects-1/#feColorMatrixElement).

Следствие для реализации градиента: матричное преобразование и линейная интерполяция совместимы до ограничения каналов, но преждевременное ограничение RGB меняет промежуточные цвета. В текущем алгоритме добавлены остановки градиента в местах пересечения каналами границ 0 и 255; это проверяемое математическое решение проекта. Укорочение видимой части линии клипом не должно растягивать палитру: её якоря вычисляются для полной, ещё не обрезанной линии.

## Подтверждённая причина дефекта

В исторической версии `e42e46ca0e4d9fb887312f0333b24fc4898f1d99` цветной полигон ядра рисовался дважды при `globalCompositeOperation = 'lighter'`. Это суммировало цвет и покрытие пикселей: ядро становилось ярче, теряло цвет и выглядело толще. Сам эталон помощника рисовал цветное ядро однократно.

Исправленная модель рисует каждое ядро один раз с `source-over`, применяет общий CSS-фильтр эталона и создаёт размытый след без второго жёсткого цветного ядра. Чтение кода и сравнение итоговых PNG подтверждают исправление именно этого дефекта; они не доказывают идентичность всех способов растеризации SVG и Canvas.

## Параметры интерфейса и расчёт толщины

Палитра, форма, длина, цикл 6,4 секунды и интенсивность свечения являются художественными настройками интерфейса. Они не описывают физический неон. Эталоном служит утверждённый контур помощника; для кнопок погоды и пород переносится его качество линии с сохранением их собственной формы и поведения.

В измеренной конфигурации кнопка помощника имела ширину 44 CSS px, а её SVG-контур — 51,0375 CSS px при ширине `viewBox` 100. Максимальная полутолщина исходной линии — 0,48 единицы SVG. Расчёт максимальной полной толщины без учёта сглаживания и свечения:

`2 × 0,48 × 51,0375 / 100 = 0,48996 CSS px`.

Это расчёт для конкретной измеренной конфигурации, а не универсальный размер всех устройств. Масштаб следует получать из фактической CSS-ширины эталона без hover-transform. При скрытом SVG ширина может требовать расчёта из определённой ширины родителя и бокового отступа. Нельзя путать номинальную геометрическую толщину с FWHM итогового свечения или количеством пикселей в PNG.

## Наблюдения при сравнении изображений

Проверены шесть непрозрачных PNG после браузерной композиции: до и после исправления в фазах 0,30; 0,45; 0,70 цикла. В каждом кадре находились исходный помощник, круглый контроль Canvas, кнопка пород 116 × 44 CSS px и кнопка погоды 117 × 18 CSS px. Canvas рисовал при backing DPR 3; DPR браузера и фактический масштаб снимков составляли 2,5. PNG имели размер 3200 × 1800 при viewport 1280 × 720. Таким образом, обозначение DPR в имени файла не заменяет проверку реальных размеров снимка.

RGB в таблице — среднее по касательной в пике поперечного профиля круглого контроля; значения округлены. Это измерение итогового изображения с CSS-свечением.

| Фаза | Контроль до | Контроль после | Эталон помощника после |
| --- | --- | --- | --- |
| 0,30 | 236, 249, 233 | 95, 160, 187 | 95, 163, 190 |
| 0,45 | 200, 249, 227 | 143, 152, 197 | 137, 153, 195 |
| 0,70 | 242, 241, 245 | 184, 134, 196 | 180, 135, 193 |

- После исправления яркая малонасыщенная доля энергии ядра равнялась нулю во всех девяти проверенных образцах Canvas. Критерий: максимальный канал не менее 127,5 и относительная цветность `(max − min) / max` не более 0,12. Это ограниченный результат выборки, не гарантия отсутствия светлых участков в любой фазе палитры.
- Средняя интегральная линейная яркость поперечного профиля уменьшилась примерно на 47% для круглого контроля, 51% для кнопки пород и 54% для погоды относительно ошибочной версии. Цвет ядра приблизился к эталону вместо белого выгорания.
- FWHM итогового профиля Canvas составляла примерно 1,24–1,45 CSS px, у эталона — 1,48–1,57 CSS px. Эти величины включают сглаживание и свечение и не равны расчётным 0,48996 CSS px геометрии.
- Полного совпадения ореола нет: у круглого контроля ширина на уровне 10% пика была 5,11–5,49 CSS px против 6,68–6,92 у эталона; интегральная энергия составляла около 80–85% эталона. Поэтому результат нельзя называть точным пиксельным совпадением.

Локальные проверочные материалы: `output/rim-parity-2026-11-05/pixel-metadata.json`, `*-raw.png`, `analyze-pixels.py`, `analyze-pixels.json`. Каталог `output` игнорируется Git и не является гарантированно сохраняемым архивом. Первые файлы без суффикса `-raw` оказались JPEG с неверным расширением и несинхронным кадром; в измерения они не включались.

## Повторная проверка при изменениях

Сравнивать один и тот же момент цикла и одинаковую палитру; учитывать реальный CSS-размер эталона, DPR растеризации и масштаб полученного PNG отдельно. Для проверки полного CSS-свечения нужен снимок после браузерной композиции: `getImageData()` исходного Canvas не включает внешний CSS-фильтр.

Регрессионные тесты проверяют однократную отрисовку ядра, режим композиции, тени, матричную палитру, необрезанные градиентные якоря, скрытый эталон, изменение размеров и DPR. Они дополняют визуальную проверку. Измерения этой заметки не являются подтверждением проверки физического iPhone или публикации релиза.

Заметка предназначена для внутреннего vault. Она не включается в клиентскую базу SendPulse/OpenAI; индексы и генераторы базы знаний ради неё не изменяются.
