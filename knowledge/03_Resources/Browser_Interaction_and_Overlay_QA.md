# Проверка интерактивных элементов и модальных слоёв

Проект: [[01_Projects/HUNDESALON_NIKA]]. Связи: [[03_Resources/Responsive_Contact_Layout]], [[03_Resources/Cloudflare_Security_Audit]]. Проверено 2026-11-14; дополнено 2026-11-16.

## Проверенные технические сведения

### Linux WebKit и ожидание готовности — 2026-11-18

- В Linux CI с Playwright1.64.1/WebKit2370 исходные `waitForFunction` завершались тайм-аутом, хотя последующие ограниченные `page.evaluate` подтверждали `.is-alive` и opacity1, видимость страницы, фокус и отсутствие JS errors. По [официальному API](https://playwright.dev/docs/api/class-page#page-wait-for-function) polling по умолчанию использует `requestAnimationFrame`; numeric polling проверяет условие таймером. Эти механизмы не взаимозаменяемы для проверки плавности анимации.
- Контроль polling50 с Playwright1.64.1 и теми же predicates/deadlines прошёл native dark/light pixel checks, но позже остановился на screenshot/locator progress. Поэтому этот первый вариант не был полным исправлением. После обновления1.65.1 полный CI2555 снова обнаружил исходный RAF timeout; timer-driven DOM-флаги переведены на polling50 с прежними deadlines, обязательными hit/stability/pixel assertions. Проверка плавности анимации этим не подменяется.
- Контролируемое обновление только Playwright/core до1.65.1/WebKit2388 с исходными RAF assertions прошло оба Linux booking сценария, включая native close/unlock/reopen. Job134484883343 в [manual A/B run](https://github.com/alanchik66/HUNDESALON_NIKA/actions/runs/44209773941) успешен; остальной диагностический workflow затем отменён и не является полным release PASS. Runtime/CSS и deadlines не менялись. Полный QA и production delivery проверяются отдельно для точного релизного commit.
- [Upstream43426](https://github.com/microsoft/playwright/issues/43426) описывает starvation Linux backdrop-filter в2370 и частичное улучшение2373+. Поздний [WebKit327701](https://bugs.webkit.org/show_bug.cgi?id=327701) fix324100 не входит в проверенный upstream base1.65.1. Наблюдаемое улучшение нашего теста не доказывает причинность одного конкретного commit. Точные source ancestry, patch queue и границы: `output/release-2026-11-17/remediation/playwright-webkit-upstream-provenance.md`.
- Pixel цвета фона не доказывает полноту glyph: в isolated GTK native-select fixture light текст подрезан, Windows PNG показывает полный текст. Fixture отличается от сайта глобальными шрифтами и modal font floor; продуктовый дефект этим не установлен. Необязательный flow screenshot также может остаться timeout при успешных native действиях. Это ограничения свидетельств, не повод менять CSS приложения ради эмулятора. Наблюдения/артефакты: `output/release-2026-11-17/remediation/linux-webkit-observations.md` и `linux-webkit-{82ec13a,36a50f6,8d848ed}/`.
- Даже после исправления frame два коротких Linux GTK контроля прошли, но полный Linux run остановился на locator visibility, а booking PNG одного короткого PASS показывал страницу под модальным окном. Эти результаты не считаются визуальным подтверждением Safari. [Playwright рекомендует macOS для наиболее близкой к Safari проверки](https://playwright.dev/docs/browsers). Выбран обязательный macOS WebKit job в Pages workflow: без его успеха publish job не запускается; Linux выполняет полный Chromium gate, локальный `qa:max` по умолчанию сохраняет оба engine. Test predicates/deadlines/native interactions/pixel guards прежние. Это смена платформы проверки, не отключение WebKit gate.
- Репозиторий HUNDESALON_NIKA проверен через GitHub API как PUBLIC2026-11-18. Для [стандартных GitHub-hosted runners публичных репозиториев](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) время выполнения бесплатно. Используется стандартный `macos-latest`, не larger runner. Это не утверждение о бесплатности других сервисов или всех будущих операций аккаунта.

### Неподвижная рамка обычной формы — 2026-11-18

- Два свежих Linux контроля1.65.1+polling50 дали один PASS и один strict hit-test FAIL: close сместилась сy16 до−87 при прокрутке `.modal-content`, не меняя собственного transform. Поэтому результат одного адресного запуска не считается доказательством стабильности. Свидетельства: `output/release-2026-11-17/remediation/linux-final-evidence-ff0f322/`.
- Причина подтверждена детерминированной Chromium регрессией: frame overflow:hidden уже имел scrollTop102; попытка +=103 дала205, close−86→−189 при неизменном frameTop8. По [CSS Overflow](https://drafts.csswg.org/css-overflow-3/#valdef-overflow-clip) hidden допускает программную прокрутку, clip её запрещает. Это та же архитектура неподвижной рамки и внутреннего scrolling body, уже используемая price-веткой.
- Исправлены три существующих ordinary frame declarations в `assets/css/page-modules.css`: базовая, step2 и её мобильное переопределение. Теперь overflow:clip; DOM, blur и анимации прежние. В `tools/booking-select-refresh.test.mjs` проверяются frame scroll rejection, scroll активного внутреннего шага, положение/hit close и последующее настоящее закрытие без сброса внутренней прокрутки.
- Адресный GREEN Chromium/WebKit4/4: frame0→0, closeY16, внутренний step37→157 и последующие native close/unlock/reopen PASS, JS errors0. Это контролируемые DOM scroll probes и реальные нажатия; они сами по себе не доказывают touch-жесты, все три шага или физический iPhone. RED/GREEN, исходные PNG и границы: `output/release-2026-11-17/remediation/close-frame-{red,green}/`.

### Динамические списки записи и значения CSS — 2026-11-17

- Обычная ветка `renderServiceList` создавала пять видимых `select` после первоначального `initSiteSelects`, поэтому они не получали общий glass-control. После вставки контейнера вызывается существующий `refreshSiteSelect`; повторное открытие не создаёт вложенные wrappers. Это подтверждённый дефект и минимальное решение проекта, а не изменение механизма записи.
- `tools/booking-select-refresh.test.mjs` проверяет реальные нативные нажатия, один `change` на выбор, закрытие и разблокировку страницы, повторное открытие и читаемый native fallback в тёмной/светлой теме. Chromium и WebKit прошли четыре сценария; это эмуляция, не физический iPhone. Скриншоты и наблюдения: `output/release-2026-11-17/remediation/select-fix/`.
- `none` является самостоятельным значением `text-shadow` и `filter`, а не элементом списка теней или цепочки фильтров. Подстановки `none, none, none` и `none brightness(1.08)` недопустимы. Новый Stylelint 18 выявил эти ошибки; они заменены валидными значениями без отключения правила. Первичные спецификации: [CSS Text Decoration](https://www.w3.org/TR/css-text-decor-3/#text-shadow-property), [Filter Effects](https://www.w3.org/TR/filter-effects-1/#FilterProperty). Проверено 2026-11-17 по исходникам проекта и lint; фактический каскад может отдельно перекрывать фильтр через `!important`.

Меню использует собственный wheel handler, нативное touch panning, `overscroll-behavior: contain` и `touch-action: pan-y`. Проверять нужно обычную прокрутку и оба края списка; одного изменения `scrollTop` в тесте для проверки жестов недостаточно.

## Наблюдения и решения интерфейса

- Центр прямоугольника DOM может быть закрыт другим элементом. В списке пород закреплённый поиск перекрывал верхнюю строку; сохранённые координаты попадали в поиск. Выбирать пункт в тесте нужно по фактическому `elementFromPoint`, затем выполнять нативное нажатие. Это наблюдение теста, а не дефект обработчика выбора.
- Hit-точки должны соответствовать форме контроля: launcher помощи имеет вычисленный `border-radius: 50%`, `clip-path: none` и размер 56.15625×56.15625 px. Нижний правый угол bounding rectangle находится вне круга и закономерно попадает в родительскую section. В Chromium/WebKit центр и четыре кардинальные точки внутри круга принимают кнопку; trusted-нажатие открывает помощь. Прямоугольные точки сохраняются как диагностическое сравнение, стили продукта не меняются ради искусственного критерия.
- Шапка меняет высоту при прокрутке; снимок экрана между измерением и касанием может сделать координаты устаревшими. Нативный locator с ожиданием готовности или повторный hit-test непосредственно перед касанием надёжнее сохранённой координаты. Программный `element.click()` не доказывает доступность элемента пользователю.
- Перед измерением движения той же монеты тест прокручивает неанимированный `.price-card__price` с `behavior: 'instant'`, затем ограниченно ждёт viewport/CSS visibility и три стабильных положения scroll root. Сам критерий изменения transform/WAAPI остаётся прежним, без `play()`, `pause()` или стилевых overrides. Свежий local diagnostic подтвердил движение видимой монеты; старый полный smoke не сохранил геометрию, поэтому его неподвижный sample нельзя уверенно объяснять `smooth` или `content-visibility`.
- Видимые плитки услуг являются `label`, а технический checkbox имеет размер 1×1 px и `pointer-events: none`. Нативное нажатие проверяется по плитке; forced check скрытого input не воспроизводит пользовательское действие.
- Мгновенный snapshot после закрытия нативного `dialog` в проверенном WebKit ещё показывал фокус на `DIALOG`. Read-only timeline сохранил восстановление прежнего `BODY` к 1039 ms; четыре адресных cart-сценария прошли с конечным ожиданием 2 s. Для такого наблюдения проверять конечный focus invariant и временные отметки, не вызывать `focus()` из harness ради успешного результата. Это измерение конкретного запуска, не универсальная гарантия времени браузера.
- Плавающая «Помощь» перекрывала правую часть кнопки cookies. Баннер теперь расположен выше launcher, но временно скрывается при активном окне записи и возвращается после закрытия. Это выбранный порядок интерфейса; его нужно проверять реальным открытием и закрытием окна без предварительного ответа на cookies.
- В мобильном окне записи launcher также перекрывал правый нижний край кнопки продолжения: DOM hit-test и снимок подтвердили наложение. При `body.booking-modal-open` скрывается весь `.hn-ai-chat`, чтобы ни launcher, ни уже открытая панель не перехватывали ввод; после закрытия состояние чата сохраняется. Проверки скрытия и восстановления добавлены в visual regression.
- Общий класс `.nav-main` скрывается на узких экранах. Повторно использующий этот класс блок `.before-after-filters.nav-main` должен явно сохранять `display: flex` и перенос строк, чтобы стили шапки не скрыли фильтры.
- У календарного шага записи мобильный `margin-inline: -1.75rem` конфликтовал с более специфичным `padding-inline: 2px`: кнопки смещались на −26 px и обрезались. После `margin-inline: 0` у `#booking-modal #step-2 .modal-buttons` левый край кнопки стал `20.390625px` при крае панели `18.390625px`; все пять точек и нативный возврат прошли проверку. `scrollLeft` панели, footer и кнопки равен нулю: причиной был каскад отступов, а не горизонтальная прокрутка. Сравнение сохранено в `output/navigation-qa-2026-11-13/calendar-footer-geometry-v8-v9.json`.
- Расширение `.custom-scrollbar-thumb--page` на контролируемой фазе 58% давало ширину 58.24 px при полосе 6 px. Ползунок перехватывал угол кнопки вне gutter. `overflow: hidden` у page track ограничивает и отрисовку, и hit-area; matched CSS-пара в Chromium mobile и WebKit desktop/mobile это подтвердила. Chromium desktop также сохранил реальный drag мышью за пределами полосы. JSON контролируемой фазы и PNG после её завершения — разные виды свидетельств; последний нельзя выдавать за снимок пика.

## Проверки и границы

- Проверять четыре локали, desktop/mobile, Chromium/WebKit, центр и четыре угла кликабельных плиток, прокрутку с неподвижным фоном, фокус, Escape, закрытие и возврат между шагами.
- Адреса ссылок и HTTP-коды, нативные нажатия и загрузка конечного документа — разные уровни доказательства. Перехваченный запрос навигации подтверждает обработку нажатия; ответ назначения проверяется отдельно.
- Не отправлять реальные заявки, заказы, отзывы, подписки и сообщения ради проверки UI. Внешние приложения `tel:`, `mailto:`, `viber:` и доступность чужих роликов нельзя считать проверенными только по валидному href.
- Основные сценарии: `tools/burger-menu-smoke.mjs`, `tools/burger-menu-scroll-smoke.mjs`, `tools/visual-regression.mjs` (также `--webkit`), `tools/price-list-smoke.mjs`, `tools/accessibility-smoke.mjs`. Свидетельства запуска и ограничения: `output/navigation-qa-2026-11-13/navigation-audit.md`.
- Эти материалы являются внутренней технической справкой и не добавляются в клиентскую базу знаний.

## Социальные плееры — 2026-11-15

- Разрешение origin в CSP не является выбором пользователя. После добавления social origins прежнее безусловное назначение `iframe.src` включало внешнюю загрузку до действия посетителя, что расходилось с собственным описанием сайта.

## Возврат фокуса меню в WebKit — 2026-11-15

- До исправления локальный headless WebKit сохранял `BODY` перед pointer click и после Escape через 400/1400 ms; открытие клавиатурой возвращало фокус корректно. Свидетельство: `output/release-2026-11-15-final/browser/webkit-focus-return-report.json`. Это не проверка физического iPhone.
- Новый тест в `tools/frontend-regressions.test.mjs` исполняет фактические обработчики и воспроизводит pointer click без изменения фокуса кнопки: до исправления только этот сценарий завершался `body !== burger`; после исправления проходят pointer/keyboard Escape и закрытие при переходе без возврата фокуса. Проверка нового собранного артефакта в браузере выполняется отдельно от этой регрессии.

На следующей четверти шага группа меняет маршрут лишь после выхода всех четырёх лап; проверка учитывает текущую фазу маха без покадрового `getBoundingClientRect`. Готовность ожидает текущий каталог, шрифты, декодирование до шести видимых изображений, атлас лап и импорт общих погодных модулей. Предыдущие сведения о пятисекундном пределе и общем CSS-звездопаде относятся к исторической версии.

Поэтому проверка по `preview.hundesalon-nika.com` подтверждает актуальную доставку ресурсов и поведение сцен, но не постоянное сохранение production-кэша. Политика шлюза не менялась.
