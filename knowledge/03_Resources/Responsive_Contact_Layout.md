# Адаптивная страница контактов

Проект: [[01_Projects/HUNDESALON_NIKA]]. Проверено 2026-11-06.

## Проверенные технические сведения

- Прямые дочерние элементы CSS Grid и непустые текстовые последовательности становятся элементами сетки; для текста браузер создаёт анонимную ячейку. Поэтому значение контакта следует целиком помещать в явный `.contact-value`, а ссылку телефона/email делать этой ячейкой. Источник: [CSS Grid, Grid Items](https://www.w3.org/TR/css-grid-2/#grid-items).
- `text-align: justify` может увеличивать промежутки между словами. На странице проекта общее правило затрагивало вводный абзац и список профилей. Для этих коротких строк задано локальное выравнивание влево. Источник: [CSS Text, Text Alignment](https://www.w3.org/TR/css-text-3/#text-align-property); наблюдение: `assets/css/style.css`, общие правила editorial text alignment.

## Решение проекта и границы наблюдения

- `de/en/ru/uk/kontakty.html`: пять явных значений, адрес и график с осмысленными переносами. `assets/css/contact-page.css`: на экране до 600px иконка слева, подпись и значение справа в двух строках; список профилей с безопасными отступами, поля формы не мельче 16px. Это дизайнерские настройки проекта, а не требования спецификации.
- Страница использует отдельный CSS после общих модулей: стили контактов не увеличивают общий CSS и не расходуют его установленный бюджет. В генераторы клиентской базы знаний эта внутренняя справка не добавлялась.
- Скриншоты пользователя показывают дополнительное дробление адреса. Участие iOS Data Detectors или перевода браузера остаётся гипотезой: DOM физического телефона не был получен. Явная обёртка предотвращает превращение вложенных фрагментов в соседние ячейки сетки.
- Локальная браузерная проверка и скриншоты: `output/playwright/contacts-iphone-2026-11-06/`. Эмуляция WebKit/Chromium не подтверждает результат на физическом iPhone; при следующих изменениях проверять узкие экраны, все локали, форму и плавающие элементы.

## Результат проверки 2026-11-06

- `after-report.json`: 42 из 42 сценариев проходят в Chromium/WebKit, все четыре локали, ширины 375/390/430/961/1440px и дополнительные русские версии на 320px. Во всех сценариях новый CSS реально загружен, горизонтальный вылет отсутствует, пять значений находятся внутри строк, поля формы имеют размер шрифта не менее 16px.
- HTMLHint четырёх страниц, Stylelint нового CSS, production build, asset budgets и `git diff --check` проходят. Общий CSS — 49890/50000 байт gzip; лимит не увеличивался. Существующий contact-map smoke проходит для восьми сочетаний языка и размера, проверки клиентской базы знаний — 20/20.

## Общая колонка значений и карта в предпросмотре — 2026-11-06

- На ширине более 600px карточка использует общую сетку и строки `subgrid` внутри `@supports`. Заголовок и соцсети занимают всю ширину. Измерения во всех локалях показали одинаковый x всех пяти значений; вариант без subgrid сохраняет прежний читаемый layout. Источник: [CSS Grid, Subgrids](https://www.w3.org/TR/css-grid-2/#subgrids); реализация: `assets/css/contact-page.css`.
- У локального backend5516 и read-only HTTPS gateway отсутствовал точный маршрут `/api/maps-config`, поэтому конфигурация карты возвращала403. На опубликованном сайте endpoint возвращал200 и признак наличия ключа. После разрешения локального маршрута реальный Google SDK сообщил `RefererNotAllowedMapError`: опубликованный ключ не разрешает localhost. Значение ключа в отчёты не сохранялось. Значение ошибки подтверждено в [Google Maps JS errors](https://developers.google.com/maps/documentation/javascript/error-messages#referer-not-allowed-map-error).
- Для предпросмотра получен готовый iframe-код через публичный интерфейс Google Maps: адрес Untere Eichstädtstraße38 → «Поделиться» → «Встраивание карт». Это обычная интерактивная карта Google без API-ключа, а не3D-режим. Source URL не конструировался из собственного `pb`. Инструкция провайдера: [Google Maps Help](https://support.google.com/maps/answer/7101463?hl=en). Production Functions, CSP и ограничения Google-ключа не изменялись.
- Preview-конфигурация возвращает `embedUrl`; клиент принимает только HTTPS `www.google.com/maps/embed` с `pb`, без credentials и `key`. Панель быстрых действий вынесена ниже iframe, чтобы не закрывать подписи Google. Все остальные `/api/` остаются закрыты, GET/HEAD разрешены только для перечисленных маршрутов; POST и обходы пути проверяются тестами.
- Реальный первый HTTPS-запрос конфигурации превысил5s, следующий прошёл. Добавлен ровно один повтор для временной сетевой ошибки/5xx, а4xx не повторяются. Таймаут охватывает полный JSON-body и всегда очищается.
- `data-map-ready` и событие iframe `load` сами по себе не доказывают работоспособность карты: Google может отобразить ошибку внутри загруженного документа. Верификация требует фактических улиц/точки и скриншота. Артефакты этой проверки: `output/playwright/contacts-desktop-map-2026-11-06/`.
- Финальная диагностика WebKit390×844 уточнила ранний timeout драйвера: карта была ниже экрана (`top995px`), iframe ожидался до прокрутки. После прокрутки (`top152px`) конфигурация пришла200 за359ms, появились `google-embed`/`ready1`, ошибок запроса и JavaScript не было. PNG не получен из-за тестового лимита screenshot2.5s; это подтверждает lifecycle, но не пиксели WebKit. Визуальное доказательство карты — Chromium PNG и проверка подключённого Chrome. Физический iPhone этим не заменяется.
