# План безопасной модульности CSS

`assets/css/style.css` сейчас является общим слоем сайта и содержит пользовательские изменения. Его нельзя механически дробить без визуального покрытия всех языков и ключевых шаблонов: порядок правил и специфичность являются частью поведения.

## Целевые слои

1. `tokens.css` — цвета, размеры, типографика, интервалы и z-index.
2. `base.css` — reset, базовая типографика и общая доступность.
3. `layout.css` — контейнеры, header, footer и сетки.
4. `components.css` — кнопки, карточки, формы, модальные окна и навигация.
5. `utilities.css` — короткие атомарные служебные классы.
6. `pages/*.css` — только уникальные правила конкретных страниц.

## Порядок миграции

- Сначала зафиксировать визуальные эталоны desktop/mobile и light/dark.
- Переносить по одному независимому блоку, сохраняя исходный порядок подключения.
- После каждого переноса запускать `npm run qa:max` и сравнивать скриншоты.
- Не использовать runtime `@import`; production-сборка должна выдавать минимальное число CSS-запросов.
- После стабилизации каждого слоя ужесточать бюджеты ресурсов.

Первый этап в текущем изменении — автоматическое визуальное покрытие и бюджеты. Физический перенос существующих правил выполняется отдельными малыми изменениями, чтобы не смешивать его с уже находящейся в рабочем дереве пользовательской переработкой дизайна.
