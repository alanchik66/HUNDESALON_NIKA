# Staging и сквозная проверка интеграций

## Назначение

Preview-развёртывание используется для проверки production-сборки и Pages Functions без отправки реальных уведомлений и без проведения платежей. В репозитории хранятся только безопасные настройки; секреты, DNS, отправители и параметры внешних кабинетов остаются в Cloudflare и соответствующих сервисах.

## Локальная проверка

```powershell
npm ci
npm run qa:max
npm run dev:cf
```

`qa:max` выполняет статическую проверку, unit-тесты Functions, production-сборку, контроль бюджета ресурсов, визуальную регрессию и smoke-проверку доступности.

## Preview-развёртывание

После явного разрешения на развёртывание:

```powershell
npm run build:production
npx wrangler pages deploy dist --project-name=hundesalon-nika --branch=staging
```

Для `[env.preview]` в `wrangler.toml` платежи и внешние уведомления выключены. Preview-секреты настраиваются отдельно в Cloudflare Pages и не должны копироваться в Git.

## Матрица E2E

1. Локально: формы проверяются с заглушками сетевых вызовов, включая таймауты, повторные запросы и постоянные ошибки.
2. Preview: проверяются маршруты, CORS/CSRF, Turnstile, валидация и ответы Functions; реальная доставка и платежи остаются выключенными.
3. Production: только после отдельного явного разрешения выполняется одна контролируемая тестовая заявка на принадлежащие владельцу тестовые адреса.
4. Внешние кабинеты: отдельно подтверждаются домен отправителя и DKIM, адресная книга SendPulse, Automation 360/CRM, журналы доставки, Google Sheets/Calendar и Telegram — если они включены.

Наличие успешного локального ответа или preview-страницы не считается подтверждением реальной доставки во внешнем сервисе.

## Критерии готовности

- `npm run qa:max` завершается без ошибок и предупреждений в stderr.
- Скриншоты четырёх сценариев навигации сохранены в `test-results/visual-regression/`.
- Нет `serious`/`critical` нарушений axe в выбранных ключевых маршрутах.
- Production-ресурсы укладываются в бюджеты `tools/check-asset-budgets.mjs`.
- Preview не отправляет уведомления и не принимает реальные платежи.
- Production E2E отмечается выполненным только после проверки записи/доставки в каждом включённом внешнем сервисе.
