# Магазин HUNDESALON NIKA

Страницы: `/de/shop`, `/en/shop`, `/ru/shop`, `/uk/shop`. Статический HTML генерируется командой `node tools/generate-shop-pages.mjs` из переводов `assets/js/shop-catalog.js`. После изменения переводов генерацию нужно повторить.

## Что работает сейчас

- Витрина с шестью направлениями ухода, фильтры по питомцу и категории, поиск, корзина с количеством и удалением.
- Хранение в браузере только ID и количества; повреждённые, неизвестные и недоступные позиции отбрасываются.
- Запрос опубликованных товаров через почтовый клиент: пользователь проверяет и отправляет письмо самостоятельно. Это запрос, а не подтверждённый заказ.
- Каталог намеренно пуст: реальных товаров пока нет. Иллюстрации направлений ухода не являются фотографиями продаваемых товаров. Не публикуются вымышленные цены, отзывы, наличие, скидки или условия доставки.

## Добавление настоящих товаров

В `SHOP_PRODUCTS` добавляется запись с полями:

```js
{
  id: 'approved-product-id',
  published: false,
  available: false,
  category: 'wash', // wash | coat | tools | paws | cats | sets
  pets: ['dog'], // dog | cat; обе категории только если подтверждено производителем
  name: { de: '', en: '', ru: '', uk: '' },
  description: { de: '', en: '', ru: '', uk: '' },
  image: '/assets/images/shop/approved-product.webp',
  priceCents: 0 // реальная согласованная цена в евроцентах
}
```

Для публикации обязательны название во всех языках, локальная фотография и положительная целочисленная цена. `published` и `available` включаются только после подтверждения товара, цены и наличия. Остатки требуют отдельного серверного источника при запуске продаж.

## Онлайн-оплата: фактическое состояние

`functions/payment.js` реализует предоплату записи, а не товары. В нём `ONLINE_PAYMENTS_HARD_DISABLED = true`; существующая платёжная защита сохранена. Магазин не вызывает этот endpoint и не объявляет возврат с платёжной страницы подтверждением оплаты.

Перед включением онлайн-продаж нужны:

1. Серверный источник товаров, остатков и цен; клиент передаёт только ID и количество. Итог, доставка и налоги рассчитываются сервером, а не берутся из корзины браузера.
2. Отдельный checkout товарных заказов, сохраняемый заказ с уникальным ID, защита от повторной отправки и атомарная работа с остатками.
3. Stripe Checkout с проверенными настройками аккаунта, подписанный webhook с отдельным типом `shop_order`, дедупликацией событий и сверкой суммы/валюты/заказа. Существующий booking webhook нельзя использовать для выдачи товаров без адаптации.
4. Согласованные способы получения, стоимость, сроки, адрес для возврата и применимые условия продажи. Их следует проверить для конкретного ассортимента до запуска.
5. Проверка тестового успешного платежа, отмены, повторного webhook, отказа оплаты, недоступного товара и восстановления после ошибки. Только затем отдельное включение реальных платежей.

Изменения в этой задаче не активируют оплату, не меняют Cloudflare-настройки и не публикуют сайт.
